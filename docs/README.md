# Repository Docker & Development Notes

## Overview

User Search is a semantic search application that indexes data from multiple sources — Active Directory, netForum, External Users, Distribution Groups, and activity logs for each — into a pgvector-backed Postgres database. Users are found via SBERT-powered nearest-neighbour search and cross-source intersection queries.

See [etl-architecture.md](etl-architecture.md) for the full ETL pipeline and database schema reference.  
See [aws-migration-plan.md](aws-migration-plan.md) for the planned AWS production architecture (RDS, Lambda, Fargate).

## Quickstart — full dev stack

Bring up all ETL services (including vectorization), the application, and Postgres:

```sh
npm run dev:up
```

Equivalent docker compose command:

```sh
docker compose \
  -f docker-compose.postgres.yml \
  -f docker-compose.app.yml \
  -f docker-compose.etl-ad-line.yml \
  -f docker-compose.etl-netforum-line.yml \
  -f docker-compose.etl-eu-line.yml \
  -f docker-compose.etl-dg-line.yml \
  -f docker-compose.genai.yml \
  up --build
```

## GenAI stack (Ollama + GenAI service)

The GenAI service and Ollama LLM are defined in `docker-compose.genai.yml` and are included in `npm run dev:up`. To start only the GenAI stack alongside an already-running Postgres:

```sh
docker compose -p user-search -f docker-compose.genai.yml up --build
```

On first run, pull the model once:

```sh
docker exec user-search-ollama-1 ollama pull llama3.1:8b
```

The chat UI is available at `http://localhost:3000` (the 💬 button in the bottom-right corner). The GenAI service API is accessible directly at `http://localhost:3001/api/chat`.

### Seeding historical change data

A one-time seed script populates `source_change_logs` and `etl_job_logs` with realistic historical data so the GenAI service has meaningful context:

```sh
python3 seed_change_logs.py
docker exec -i user-search-postgres-1 psql -U postgres -d appdb < seed_change_logs.sql
```

## Regenerating synthetic data

All synthetic data is generated by `generate_synthetic.py` at the workspace root. It reads Active Directory data from `services/etl-ad-line/data/primary.json` (committed seed file) and writes all other datasets directly to the `data/` directory of each line service.

```sh
python3 generate_synthetic.py
```

This writes `primary.json` and `logs.json` under each `services/etl-*-line/data/` directory.

## Run a single line ETL service

Example — run only the Active Directory line ETL (primary + activity logs):

```sh
docker compose -f docker-compose.etl-ad-line.yml up --build
```

## Run app + Postgres only

```sh
docker compose -f docker-compose.postgres.yml -f docker-compose.app.yml up --build
```

## Initialising the database on an existing Postgres instance

If Postgres is already running (init scripts have already been applied), execute any new schema scripts manually:

```sh
docker exec -i <postgres-container> psql -U postgres -d appdb < infra/db/init/<script>.sql
```

## Code quality

```sh
# Lint all service JS
npm run lint

# Run all unit tests
npm test

# Lint markdown docs
npm run lint:docs
```

ESLint is configured in `eslint.config.mjs` with Node.js globals, `no-unused-vars`, `eqeqeq`, `no-var`, and `prefer-const`. Jest globals are automatically applied to `**/test/**/*.js` files.

## Host data directories (dev)

- `data-output/postgres/` — Postgres data directory (bind-mounted for persistence between restarts)
- `data-output/model-cache/` — Cached SBERT model weights (shared across all vectorize containers)
- `data-output/<service>/` — JSON output written by each ETL index service

On macOS Docker Desktop, named volumes may perform better for the Postgres data directory; consider switching to a named volume in CI/production.

## Environment

Create a local `.env.dev` (add to `.gitignore`) with dev secrets, e.g.:

```
POSTGRES_PASSWORD=postgres
PGPASSWORD=postgres
```

## CI

Build all images for CI using the base, Postgres, and app fragments:

```sh
docker compose \
  -f docker-compose.postgres.yml \
  -f docker-compose.app.yml \
  -f docker-compose.etl-ad-line.yml \
  -f docker-compose.etl-netforum-line.yml \
  -f docker-compose.etl-eu-line.yml \
  -f docker-compose.etl-dg-line.yml \
  -f docker-compose.genai.yml \
  build
```
