# M365 Governance App — Capability Inventory

## 1. Overview

- **App purpose (from README/code):** User Search is a proof-of-concept semantic search and AI-agent platform that consolidates account/identity data from six sources — Active Directory, netForum, External Users, Distribution Groups, M365 Group Memberships, and SharePoint Permissions (plus per-source activity/sync logs) — into a single searchable, vector-backed store, with an LLM tool-calling agent layered on top for account operations, M365 service-desk actions, and governance lookups ([docs/README.md](../docs/README.md), [docs/executive-overview.md](../docs/executive-overview.md)).
- **Tech stack (languages, frameworks):** Node.js 22 / CommonJS (Express ^4.21.0) for all services; Python 3.x for synthetic data generation only ([docs/technology-stack.md](../docs/technology-stack.md), [package.json](../package.json)).
- **Hosting/runtime model:** Local proof-of-concept — Docker Compose (9 fragments: postgres, app, genai+ollama, 6 ETL lines) run as containers on a single host ([docker-compose.app.yml](../docker-compose.app.yml), [docker-compose.genai.yml](../docker-compose.genai.yml), [docs/README.md](../docs/README.md)). A future AWS target (RDS, Lambda, EKS, Bedrock) is documented as a plan only, not implemented ([docs/next-steps/aws-migration-plan.md](../docs/next-steps/aws-migration-plan.md)).
- **Auth model (app-only vs delegated; list Graph/API scopes/permissions found):**
  - **Currently: no authentication or authorization exists.** [docs/next-steps/saml-access-management.md](../docs/next-steps/saml-access-management.md) states explicitly: "Authentication: **None** — the application is unauthenticated; all endpoints are open" and "Authorisation: **None** — all users have equal access to search, lookup, chat, ETL status, and all 37 agent tools." (that count is stale — the agent now exposes **50** tools; see `AGENT_TOOLS` in [services/genai/index.js](../services/genai/index.js).)
  - The app front end is gated only by a single shared static `API_KEY` value injected into the served HTML, not per-user identity ([services/app/src/index.js](../services/app/src/index.js) line 11, lines 68-72).
  - Graph auth, when configured, is **app-only** OAuth 2.0 client-credentials via `@azure/identity`'s `ClientSecretCredential`, using the single scope `https://graph.microsoft.com/.default` ([services/genai/graph-client.js](../services/genai/graph-client.js) lines 3, 63-71). No delegated/user-context Graph auth is present.
  - SAML SSO + RBAC (`viewer`/`analyst`/`operator`/`admin`) is a documented **future** plan, not implemented code ([docs/next-steps/saml-access-management.md](../docs/next-steps/saml-access-management.md)).
- **External dependencies / SDKs relevant to M365:**
  - `@microsoft/microsoft-graph-client` and `@azure/identity` are `require()`d conditionally in [services/genai/graph-client.js](../services/genai/graph-client.js) lines 42-49, but **neither package is listed in [services/genai/package.json](../services/genai/package.json)**, meaning a live-credential configuration would fail at runtime with the code's own thrown error ("Graph client packages are not installed") unless installed manually.
  - `@xenova/transformers` (SBERT `all-MiniLM-L6-v2`) for embeddings — not M365-specific, used for search only ([docs/technology-stack.md](../docs/technology-stack.md)).
  - `node-cron` (`^3.0.3`) was added to [services/genai/package.json](../services/genai/package.json) for the new daily scheduled-report job — not M365-specific, but a new runtime dependency.
  - No PnP (PnPjs / PnP PowerShell) libraries found anywhere in the codebase.

## 2. M365 Data & Integration

- **M365 workloads touched:**
  - **Entra ID / Azure AD** — user accounts, guests, licenses, MFA, Conditional Access, device compliance, BitLocker, app consents, risky users (via `graph-client.js` mock/real calls in [services/genai/index.js](../services/genai/index.js)).
  - **Exchange/M365 mailbox** — mailbox access, email aliases, out-of-office (tools `grant_mailbox_access`, `add_email_alias`, `get_out_of_office`, `set_out_of_office`).
  - **Teams** — channel membership (`add_to_teams_channel`).
  - **OneDrive** — `grant_onedrive_access`.
  - **M365 Groups / Distribution Groups** — local ETL tables `m365_group_memberships` and `distribution_groups`, plus agent tools `add_to_group` / `add_to_m365_group`.
  - **SharePoint** — permissions only, via the `sharepoint_permissions` ETL table ([docs/etl-architecture.md](../docs/etl-architecture.md)); no live Graph/SharePoint API calls found (no code references SharePoint Graph endpoints).
  - **Not found in codebase:** Purview/sensitivity labels, DLP, retention, or Teams/Yammer content scanning.
- **Microsoft Graph endpoints / APIs called (list with file references), all in [services/genai/index.js](../services/genai/index.js) via `graphClient`:**
  - `/reports/getOffice365ActiveUserDetail(period='D90')` — inactive license report (`executeListInactiveLicenses`, ~line 1555).
  - `/users?$filter=userType eq 'Guest'&$select=...` — stale guests (`executeListStaleGuests`, ~line 1604).
  - `/oauth2PermissionGrants?$filter=principalId eq '{id}'` and `/oauth2PermissionGrants/{id}` (DELETE) — list/revoke app consents (`executeListAppConsents` ~line 2328, `executeRevokeAppConsent` ~line 2351).
  - User path helper `graphUserPath(email, suffix)` builds `/users/{email}/{suffix}` style paths used by MFA, license, mailbox, alias, OOF, Teams, OneDrive, device-compliance, and BitLocker tool executors (~line 1345).
  - All calls above run through the mock client in [services/genai/graph-client.js](../services/genai/graph-client.js) (`mode: 'mock'`) unless `ENTRA_TENANT_ID/CLIENT_ID/CLIENT_SECRET` are set — in the mock, every call returns an empty/stub payload, i.e. **no live Graph data is ever retrieved in the current deployment**.
- **Data ingestion pattern:** Scheduled — each ETL "line" service runs on startup and then hourly via `node-cron` (`CRON_SCHEDULE=0 * * * *`), reading local synthetic JSON files (`data/primary.json`, `data/logs.json`), not live APIs ([docs/etl-architecture.md](../docs/etl-architecture.md), [docs/technology-stack.md](../docs/technology-stack.md)). Governance/Graph detection tool calls in the agent remain **on-demand** (triggered by a chat message or dashboard page load), not scheduled — but report **export** is now also scheduled: `services/genai` runs its own daily `node-cron` job (`REPORT_CRON_SCHEDULE`, default `0 6 * * *`) that snapshots the current `governance_violations`/`source_change_logs` tables to CSV; it does not itself re-run detection (see §3c "Scheduled scanning").
- **Caching / persistence / storage used:** PostgreSQL 15 with `pgvector` (384-dim embeddings, HNSW cosine indexes) is the sole persistence layer for all six data lines plus `agent_tickets`, `access_requests`, `chat_messages`, `etl_job_logs`, `source_change_logs`, `governance_violations`, and `scheduled_reports` ([infra/db/init/](../infra/db/init/), [docs/etl-architecture.md](../docs/etl-architecture.md)). SBERT model weights are cached to a Docker volume; no Graph response caching layer exists beyond the per-secret in-memory cache proposed (not implemented) in [docs/next-steps/genai-production-update.md](../docs/next-steps/genai-production-update.md).
- **Throttling / paging / large-tenant handling:** **Not found in codebase.** No retry/backoff, `$top`/`@odata.nextLink` paging loop, or throttling (429) handling exists in `graph-client.js` or `index.js`; the one paged call (`list_stale_guests`) only sets `$top` on a single request with no follow-up paging.

## 4. Architecture Notes

- **Key modules/services and responsibilities:**
  - `services/app` — Express search API + static UI (search box, Compliance Posture / Activity Trends / Reports dashboard panels); executes stored-procedure search/lookup/intersection queries and proxies agent/ticket/violation/compliance/trend/report calls to `services/genai` ([services/app/src/index.js](../services/app/src/index.js), [services/app/src/public/index.html](../services/app/src/public/index.html)).
  - `services/genai` — Express service hosting the 50-tool LLM agent, Graph client wrapper, CSV export helper, and all action executors ([services/genai/index.js](../services/genai/index.js) — ~4,180 lines, [services/genai/graph-client.js](../services/genai/graph-client.js), [services/genai/validation.js](../services/genai/validation.js), [services/genai/csv.js](../services/genai/csv.js)).
  - `services/etl-ad-line`, `etl-netforum-line`, `etl-eu-line`, `etl-dg-line`, `etl-m365-line`, `etl-sp-line` — six independent cron-scheduled ingestion services, one per data source, each sharing one SBERT model instance and Postgres pool ([docs/etl-architecture.md](../docs/etl-architecture.md)).
  - `services/postgres` — pgvector-enabled Postgres 15 container; all query logic lives in PL/pgSQL stored procedures under `infra/db/init/12_stored_procedures.sql`.
- **Data model summary (main entities/tables):** `active_directory` / `active_directory_activity_logs`, `netforum_members` / `netforum_activity_logs`, `external_users` / `external_user_activity_logs`, `distribution_groups` / `distribution_group_sync_logs`, `m365_group_memberships` / `m365_membership_change_logs`, `sharepoint_permissions` / `sharepoint_permission_change_logs`, plus cross-cutting `etl_job_logs`, `source_change_logs`, `chat_messages`, `agent_tickets`, `access_requests`, `governance_violations`, `scheduled_reports` (all under [infra/db/init/](../infra/db/init/)).
- **Extensibility points (where new policies/features would plug in):**
  - New agent tools are added to the `AGENT_TOOLS` array plus a corresponding `execute*` function and dispatch case in `executeToolCall` in [services/genai/index.js](../services/genai/index.js) (currently ~4,180 lines in a single file).
  - New Graph endpoints would be added as additional `.api(path)` calls through the existing `graph-client.js` wrapper, which already supports a real/mock switch.
  - New ETL sources would follow the existing per-line pattern (`runPrimary()` / `runLogs()`, its own compose fragment, and numbered `infra/db/init/*.sql` schema file).
  - New governance checks plug into `runGovernanceScan()` — add a detector, push findings with a `violationType`/`severity` into the `found` array, and it is automatically tracked, scored, and exportable.
- **Notable constraints or tech debt affecting future work:**
  - No authentication/authorization at all — a hard blocker before any production or even non-trivial internal rollout ([docs/next-steps/saml-access-management.md](../docs/next-steps/saml-access-management.md)).
  - `services/genai/index.js` is a single ~4,180-line file containing tool definitions, validation, and all executors — no modularization by capability domain (this grew from ~2,900 lines during this audit cycle as governance/reporting tools were added, making the case for modularization stronger, not weaker).
  - Graph SDK packages (`@azure/identity`, `@microsoft/microsoft-graph-client`) are referenced in code but absent from `package.json`, so enabling live Graph mode would fail without a manual `npm install` step ([services/genai/graph-client.js](../services/genai/graph-client.js), [services/genai/package.json](../services/genai/package.json)).
  - All "write" actions (provisioning, disable, group changes, license changes, guest revocation, etc.) operate on the local Postgres mirror only; none reach real Entra ID/M365/NetForum systems yet — explicitly documented as the next required phase ([docs/next-steps/genai-production-update.md](../docs/next-steps/genai-production-update.md)).
  - No retry/backoff/paging/throttling handling for Graph calls (see §2).
  - `infra/db/init/*.sql` only runs on a **fresh** Postgres volume — the two newest schema files ([17_governance_violations.sql](../infra/db/init/17_governance_violations.sql), [18_scheduled_reports.sql](../infra/db/init/18_scheduled_reports.sql)) will not apply to an already-initialized `data-output/postgres/` volume without a manual reset or running the SQL by hand, i.e. schema evolution has no migration tooling.
  - The daily scheduled-report cron (`runScheduledReports`) exports whatever is currently in `governance_violations` — it does not itself trigger `runGovernanceScan()`, so a scheduled export can silently go stale if no one has triggered a scan (chat tool or dashboard load) since the last change.
